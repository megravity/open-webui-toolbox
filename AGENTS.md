# AGENTS.md

Working rules for coding agents (and humans) in this repository. Follow them
when editing code, docs, or instance customizations here.

## Project snapshot

- `cli/ow` is a thin launcher for the `ow/` package: `ow/config.py` stores
  configuration and setup, `ow/client.py` is the raw authenticated API client.
- `functions/sync.py` applies conflict-checked function updates; it reads
  `registry.json`, which maps function IDs to local source files.
- `filters/` and `visual-style/` hold instance assets with their own notes.
- The roadmap lives in [PLAN.md](PLAN.md); release history in
  [CHANGELOG.md](CHANGELOG.md) plus annotated `vX.Y.Z` git tags. Update both
  per the rules below; mark PLAN.md phases as shipped when they land.

## Required checks before calling a change done

- `python3 -m unittest discover -s functions -p 'test_*.py'` and
  `python3 -m unittest discover -s tests -p 'test_*.py'` — both must pass. Add
  tests for new or changed logic; do not weaken existing assertions.
- `python3 cli/ow --help` and `python3 functions/sync.py --help` — must exit 0
  after touching either entry point.
- Tests and validation must not perform live API calls. Verify real-instance
  behavior manually and read-only; keep automated flows instance-free.

## Language and compatibility

- CLI and tooling: Python 3.9+ syntax, standard library only. No new runtime
  dependencies without recording why in the changelog entry.
- User-facing strings (help text, error messages, prompts) are behavior. Keep
  them stable; any deliberate wording change is a changelog entry.

## Versioning

- The project version is the latest annotated `vMAJOR.MINOR.PATCH` tag. There
  is no version file; do not add one. Early stage stays 0.x until the CLI and
  sync tooling are declared stable.
- SemVer meaning in this repo:
  - PATCH: fixes and documentation with no user-visible behavior change.
  - MINOR: new capabilities, including added sync adapters or new commands.
  - MAJOR: breaking changes — removed or renamed commands/options, changed
    file formats (`registry.json`, baseline state), or config paths requiring
    user migration.
- Per-function docstring versions (`version: MAJOR.MINOR.PATCH` in managed
  source files) are independent of the repo version. `functions/sync.py`
  refuses pushes of a managed source whose version did not increase, so every
  change to a registered function file bumps its docstring version. The
  registry validates that format strictly.

## Changelog

- Structure follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/):
  `[Unreleased]` plus `vX.Y.Z — YYYY-MM-DD` sections with Added, Changed,
  Deprecated, Removed, Fixed, and Security subsections as applicable.
- A commit that changes user-visible behavior includes its changelog entry
  under `[Unreleased]` in the same commit. Docs-only commits may skip it.
- Releasing: move `[Unreleased]` into a new `vX.Y.Z — YYYY-MM-DD` section and
  tag the release commit: `git tag -a vX.Y.Z -m "Short description"`. The
  release commit contains only the changelog promotion.

## Housekeeping

- Never commit instance credentials, API keys, valve values, or webhook URLs.
  Secrets belong outside this repository.
- Test fixtures are synthetic. Never copy a value from a live instance into
  `tests/fixtures/`; follow the garbling rules in
  [`tests/fixtures/README.md`](tests/fixtures/README.md) and let
  `tests/test_fixtures.py` verify the result.
- Generated bytecode and editor droppings never enter version control.

## Commit style

- Subject: short, imperative, sentence case; body explains rationale when
  non-obvious. One logical change per commit.
